# 依存とランタイムの陳腐化点検 短報(2026-08)

作成日: 2026-08-01 / 担当: Claude Code / 対象 main: PR #54 マージ後(現行基準線 591)
関連: [2026-08 技術偵察レポート](ai-landscape-2026-08.md) §4 P3 / Issue #56

> **位置づけ。** 本短報は依存の**陳腐化点検**である。**コア依存(stdlib + PyYAML + idna + PyNaCl)は変更しない**。
> **新規依存は追加しない**(既存依存への**バージョン制約付与のみ**であり、絶対制約7が禁じる「新規依存追加」には当たらない。
> よって ADR 判断は不要)。変更は `pyproject.toml` の `api`/`dev` extra への**メジャー上限固定**に限定する。

---

## (1) 点検範囲と結論(先出し)

| 対象 | 判断 | 措置 |
|---|---|---|
| `requires-python = ">=3.11"` | **現状維持** | 変更なし(下記 §2) |
| コア依存 PyYAML / idna / PyNaCl | **現状維持(無制約)** | 変更なし。理由は §4 |
| `api` extra: fastapi / pydantic / uvicorn | **メジャー上限を固定** | §3 |
| `dev` extra: pytest / httpx | **メジャー上限を固定** | §3 |
| `azazel-fabric`(api extra)| **現状維持(タグ固定 @v0.3.0)** | 変更なし(ADR-0010) |

要旨: **未ピンの `api`/`dev` 依存が、将来の破壊的メジャー更新でクリーンインストール / CI を予告なく壊すリスク**があった。
これをメジャー上限固定で塞ぐ。コア依存と Python 下限は Pi 4 ターゲットの安定性を優先し据え置く。

---

## (2) Python 下限(`requires-python = ">=3.11"`)

- **現状維持。** 下限 3.11 は Pi 4 のターゲット OS が供給する系列に合わせた既決値。下限を 3.12+ へ引き上げると
  実機の provisioning を壊しうる(Pi 4 実機検証は issue #21 の残タスク)。8月時点で 3.11 のセキュリティサポートは
  継続中であり、下限を上げる差し迫った理由はない。→ **変更しない。**
- 上限は設けない(Python は後方互換性が高く、上限固定は不要な churn を生むため)。

## (3) `api`/`dev` extra のメジャー上限固定

点検時に venv で解決された実測バージョン(`pip freeze`、Python 3.11.15)を基準に、**次のメジャーを上限**として切る。
現行解決版はいずれも新制約を満たすため、**再解決による破壊はない**(据え置きインストールで挙動不変)。

| パッケージ | 実測(2026-08)| 付与する制約 | 理由 |
|---|---|---|---|
| fastapi | 0.141.1 | `>=0.115,<1` | 0.x 系列。将来の 1.0 リライトを跨がない。api extra 限定。 |
| pydantic | 2.13.4 | `>=2,<3` | **v2 前提を明示**(v1 とは非互換 API)。ADR-0010 の Fabric も pydantic v2 前提。 |
| uvicorn | 0.52.0 | `>=0.30,<1` | 0.x 系列。1.0 を跨がない。 |
| pytest | 9.1.1 | `>=8,<10` | メジャー間で破壊的変更あり。8/9 を許容し 10 を跨がない。 |
| httpx | 0.28.1 | `>=0.27,<1` | 0.x 系列。テストクライアント用途(dev)。1.0 を跨がない。 |

- **ハッシュピン・厳密ピンは行わない**(CLAUDE.md「ハッシュまでは不要、メジャー固定で可」)。上限固定で CI 再現性を確保しつつ、
  マイナー/パッチ更新は許容して dependabot churn を最小化する。
- starlette は fastapi の推移的依存であり直接制約は付けない(fastapi の上限が実質的に境界を与える)。

## (4) コア依存を据え置く理由

- PyYAML / idna / PyNaCl は**成熟・低頻度更新**で、メジャー破壊のリスクが `api`/`dev` 群より小さい。
- #56 / P3 のスコープが明示的に「コア依存は変更しない」。本短報はそれに従う。
- 将来コア依存にも上限を付ける選択肢は残る(それも新規依存追加ではないため ADR 不要)。ただし本短報では**推奨に留め、実施しない**。

## (5) 絶対制約との整合性

- **⑦依存最小性を強化**する方向。**新規依存の追加はなし**(既存依存へのバージョン制約付与のみ)。ADR 不要。
- コア依存不変・Fabric タグ固定不変・Python 下限不変。ランタイム挙動・スコアリング・公開契約に影響しない。
- 検証: `pip install -e ".[api,dev]"` が新制約下で解決すること、`python tools/docs-sync-check.py` 緑、
  `python -m pytest tests/unit -q` が**現行基準線(591)を減らさない**ことを本 PR で確認する。

## (6) フォローアップ(本短報スコープ外・要オーナー判断)

- API 依存の**メジャー更新自体**(例: 将来 fastapi 1.0 / pydantic 3 へ追随)は、別 PR で実施し
  `pytest tests/unit` 全緑(現行基準線を減らさない)を条件にする。上限固定はその更新を**意図的なレビュー対象**に変える装置。
