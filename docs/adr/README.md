# Architecture Decision Records

The design questions resolved (or explicitly deferred) with rationale. ADR-0001
through 0008 were left open in the initial concept discussion; ADR-0009 records
the Phase 2 Behavioral CTI lane; ADR-0010 ratifies adopting Azazel-Fabric
`cti_contracts` at the API boundary:

| ADR | Question | Decision |
|---|---|---|
| [0001](0001-repository-naming.md) | Repository / product name | **Accepted (2026-07-10)** — formal name `Azazel-Knowledge Advisor`, AZ-04, repo `01rabbit/Azazel-Knowledge` (formerly `Azazel-CTI`); namespace `azazel_knowledge` |
| [0002](0002-data-model.md) | STIX 2.1 vs. lightweight native model | Native model internally; STIX 2.1 at boundaries only |
| [0003](0003-database.md) | SQLite vs. PostgreSQL | SQLite WAL; PostgreSQL only on measured Phase 2 triggers |
| [0004](0004-sync-strategy.md) | Pull / push / USB / differential sync | Scheduled pull online + signed offline bundles (full & differential) |
| [0005](0005-edge-protocol.md) | REST / gRPC / MQTT; evidence format | REST+JSON and TAXII 2.1; JSONL evidence, no bespoke format |
| [0006](0006-scoring.md) | Scoring and weighting | Deterministic weighted YAML config, mandatory reason breakdown |
| [0007](0007-rule-generation.md) | How far to automate rule generation | Advisory drafts with provenance; never auto-deploy |
| [0008](0008-research-theme.md) | Black Hat research framing | "CTI-optimized delaying defense" friction loop, not "lightweight CTI node" |
| [0009](0009-behavioral-cti.md) | Phase 2 Behavioral CTI: envelope, tier, authority, ML | Separate additive lane; own `behavior_config_hash`; local-tier rebuildable; advisory-only + shadow-gated; no ML; no AI attribution |
| [0010](0010-adopt-fabric-cti-contracts.md) | Adopt `azazel_fabric.cti_contracts` at the API boundary? | **Accepted (2026-07-10)** — adopt `azazel-fabric` as an `api`-extra-only dependency for boundary payload validation; scope `api/`+`taxii/` only, never `scoring/`/`correlate/`/`core/`; additive, shapes unchanged. Originally tag-pinned `v0.3.0`; **pin in force is `v0.9.0rc6`** per ADR-0020 and `pyproject.toml` |
| [0011](0011-deception-observation-ingest.md) | AZ-06 deception-observation ingest + effectiveness advisory | **Accepted (2026-08-15)** — effectiveness boundary; advisory-only |
| [0012](0012-mitre-engage-ingest.md) | MITRE Engage ingest | **Accepted — implemented (verified 2026-09-19)** — `feeds/adapters/engage.py`, `engage_activity`/`engage_attack_map` + `feed_state.license`, and the deferred `engage_refs` seam on `/v1/context` have all shipped; advisory-only, match-gated, outside the scoring 7-tuple; no new dependency |
| [0013](0013-yara-sigma-corpus-ingest.md) | YARA/Sigma rule-corpus ingest as knowledge | **Accepted — implemented (verified 2026-09-19)** — rule text + metadata stored as intel-tier knowledge, never a scanner; Sigma/YARA adapters, `0003_rule_corpus.sql` and the `rule_refs` seam (identity only, never rule bodies) shipped; no `yara-python`/`pysigma`, enforced by `tests/unit/test_no_rule_execution.py` |
| [0014](0014-epss-advisory-ingest.md) | EPSS exploit-probability ingest as advisory context | Proposed (design spike) — intel-tier `epss_score`, own `epss_generation` out of the scoring 7-tuple, secondary context only (never a scoring input), stdlib-only, no new dependency; implementation demand-gated |
| [0017](0017-lite-is-full-only.md) | Do Knowledge Lite bundles need differentials? | **Accepted (2026-09-19)** — no; Lite is always `kind: full`. D4's mandatory expiry retires stale rows without tombstones, Lite is bounded by design so deltas save little, and a base chain would weaken the byte-identity claim. The general bundle path keeps its differentials |
| [0016](0016-fabric-pin-v0-8-0.md) | Move the Fabric api-extra pin to `v0.8.0`? | **Accepted (2026-09-19)** — aligns with Edge and Deception and with the series R0 reference candidate; 817 tests green and every imported symbol verified against the tag; scope unchanged (api-extra only, never core) |
| [0015](0015-knowledge-lite-bundle.md) | Knowledge Lite bundle profile for Nexus/Boot | **Accepted — implemented (2026-09-19)** — a **profile** of the existing signed bundle, not a second format; deterministic selection from a pinned tuple; capacity ceilings fail closed rather than truncate; export denies local-sensitive data by default with canary tests; build never touches `local.db` or the active generation; Knowledge produces and signs, consumers own caching and trust. Shipped and verified the same day; D4 was extended (a dataset may declare itself exempt from the freshness window, for a catalogue whose timestamp is about the entry rather than observation here) and five of its own statements have been corrected in place (the archive-safety inventory; a gap-analysis enumeration that was not exhaustive; a factually wrong reason for sparse-member coverage; and D5b, where four gates became six). Remaining items tracked on [#73](https://github.com/01rabbit/Azazel-Knowledge/issues/73) |
| [0018](0018-cross-edge-actor-inference.md) | Who decides that an actor at one Edge is the actor at another? | **Accepted (2026-09-19)** — Knowledge infers the linkage itself from observable evidence and reports it as advisory data with confidence and a complete `reason[]`, in its own field **alongside, never over**, the Edge-supplied `actor_cluster_key`; the inference must not reach `behavior_similarity`'s `cross_cluster_score` (circular); weights and thresholds are deliberately left to measurement |
| [0019](0019-fabric-pin-v0-9-0rc5.md) | Which Fabric tag is the current Knowledge API-extra pin? | **Accepted (2026-11-03, owner-merged PR #114)** — published pre-release `v0.9.0rc5` (`450d950…`) replaces interim `v0.9.0rc2` and earlier `v0.8.0`; API-extra-only scope and product version remain unchanged; current-main CI passed 1,595 unit tests |
| [0020](0020-fabric-pin-v0-9-0rc6.md) | Move the Fabric api-extra pin to `v0.9.0rc6`? | **Accepted (2026-11-05, owner-merged PR #118; superseded by ADR-0021)** — published pre-release `v0.9.0rc6` (`0233813…`, digest `f1b7690…`) replaces `v0.9.0rc5`; non-additive in Fabric (#65, #23, #72); the four additive `OutcomeObservationEnvelope` fields are accepted and kept in `raw` only; API-extra-only scope and product version unchanged |
| [0021](0021-fabric-pin-v0-9-0.md) | Move the Fabric api-extra pin to the stable `v0.9.0`? | **Accepted (owner-merged PR #<PR番号>)** — stable `v0.9.0` (`ee2ab8c…`, digest `5107054…`) replaces `v0.9.0rc6`; contract surface identical to `rc6`; `cti_contracts` stays experimental in Fabric (no compatibility promise); API-extra-only scope and product version unchanged |
