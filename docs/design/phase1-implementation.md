# Azazel-Knowledge (formerly Azazel-CTI) Phase 1 — FINAL Implementation Design (v4, post round-5 adversarial feedback)

Binding constraints (violating any is CRITICAL): advisory-only, no enforcement channel anywhere in the codebase; deterministic YAML-weighted scoring with mandatory complete `reason[]`, separate `threat_score`/`confidence`, no ML in the verdict path; offline-first — nothing in the query path depends on internet; signed anti-rollback bundles; SQLite WAL behind a repository layer; REST+JSON + TAXII 2.1 boundary, JSONL evidence, STIX at boundaries only; Pi 4 budgets (lookup p95 < 50 ms, context p95 < 250 ms, RSS < 2 GB, ~10M indicators); rule generation = advisory drafts only, never auto-deploy; `reaction` is core schema. Round-5 fixes are tagged **[F-n]** and registered in S12.

## 2. Process model and storage

Two containers, one writer:

- **`api`** (1280 MB): gunicorn/FastAPI, 3 `post_fork` workers. Lookup/context/read routes and **ingest routes are sync `def`** on bounded threadpools (query pool and a separate ingest pool), so spool fsync never touches the event loop **[F-4]**. Read-only WAL connections only; a static contract test asserts no router module can open a write-mode connection. Pools and `GenCache` constructed `post_fork` only (`assert_no_inherited_connections`).
- **`worker`** (640 MB): the sole SQLite writer for live databases, under exclusive `flock()` on `var/run/writer.lock` (stray second writer exits non-zero). Runs `db/writer.py:PrioritySingleWriterQueue` with fixed priority classes **[F-3]**: **P0** audit tail into `advisory_log` + reaction linkage resolution; **P1** ingest spool drain + reaction classification; **P2** feed DML, `ttl_sweep`, stats aggregation; **P3** retention pruning. Any single transaction holds the write lock <= 50 ms (checkpointed batches); P0 preempts between batches. **Bundle generation builds run in a separate low-priority subprocess writing only to the not-yet-live `gen-<N+1>/intel.db`** — a different file, so a multi-minute build never contends with the live writer; the only live-writer actions are the final symlink swap and anchor update **[F-3]**.

**Two-database storage [F-1] — structural fix for the round-5 critical.** Feed/bundle-replaceable intelligence and local immutable research data live in separate SQLite files:

- `data/db/gen-<N>/intel.db` — `ioc`, `ioc_source`, `ioc_cidr`, `kev`, `attack_*`, external `campaign` + joins, `feed_state`. Generation dirs; `current` symlink names the live generation. Bundle import builds `gen-<N+1>` and atomically repoints. Online per-feed pulls are incremental DML inside the live generation (full-replace tables via `DELETE; INSERT...SELECT` from `_stage` in one transaction; `ioc`/`ioc_source` batched, cursor-resumable).
- `data/db/local.db` — permanent, never in any generation dir, never written or read by bundle import/build, own migration chain: `reaction`, `reaction_trust_event`, `observation`, `observation_stats`, `reputation`, `advisory_log`, `edge_reported_ioc`, `pattern` + `pattern_index`, `rule_draft`, `bundle_state` (mirror only, see S7), `api_client`, `feed_quarantine`.

A generation swap therefore *cannot* discard reactions/observations — there is no carry-forward step to get wrong. Cross-DB references use a stable `entity_key = sha256(type||0x00||normalized_value)[:16]` instead of generation-local `ioc_id`s (`reputation`, `observation`, `edge_reported_ioc` key on it). `repository.py` opens one read connection per pool slot to `local.db` and ATTACHes the pinned `current` intel generation; it resolves `current` once per pool-acquire and recycles on `readlink` mismatch — no stale `-wal` replay across generations. Contract test `test_local_rows_never_decrease_across_full_import` asserts `reaction`/`observation`/`advisory_log`/`edge_reported_ioc` counts are non-decreasing across a full bundle import.

**Memory ceiling — computed, not aspired.** Per-worker `GenCache` cap reduced to **64 MB** (3 x 64 = 192 MB total, replacing the 288 MB duplication flagged in round 5; a shared-memory cache is deferred, tracked in S13) **[F-11]**. GeoIP/ASN mmap read-only, shared post-fork, counted once (64 MB); DB page residency <= 320 MiB combined Pss across both processes. `azctl check-config` prints the arithmetic at boot; the 30-min Pss soak is a drift detector.

## 3. SQLite DDL summary (all tables STRICT, WAL)

`migrations/intel/0001_init.sql`:

- **`ioc`** — `ioc_id INTEGER PK`, unique `(type, value)`; values normalized per normalize/ (see [F-15]); per-type partial indexes on hot types; materialized `agg_raw_confidence`, `agg_next_expiry`, `agg_computed_at` make lookups one-row reads. `ttl_sweep` (60 s, P2) recomputes aggregates for expired-source rows only — an expired source backs a served number for at most one sweep interval.
- **`ioc_source`** — `(ioc_id, feed_id)` PK, `source_confidence`, `first_seen/last_seen/expires_at`, `intel_generation`, `flagged_critical_infra`. Per-feed confidence/TTL from `config/feeds.yaml`: `urlhaus:85, malwarebazaar:80, threatfox: cap 90, edge_reported:35` (**`cisa_kev` removed** — KEV never appears in `ioc_source` or `sources[]` **[F-14]**); TTLs e.g. `urlhaus.ip:14d`, hashes 365 d, `edge_reported:3d`.
- **`ioc_cidr`** — packed 4-byte keys, `WITHOUT ROWID`, non-overlapping merged range tables per tier (host, /24, /16, ASN).
- **`kev`** — separate, shadow-swapped, no TTL; scores only through `cve_exploited`.
- **`attack_technique` / `attack_mitigation` / `attack_relation`** — flattened, join-free, `attack_version`-pinned.
- **`feed_state`**, `_stage` tables, `stats_meta` (`intel_generation`, `local_generation` determinism counters).

`migrations/local/0001_init.sql`:

- **`reaction`** — core schema, immutable (UPDATE/DELETE-rejecting triggers), unique `(edge_id, actor_key, action_applied, applied_at, classifier)`; `reaction_window_s NOT NULL`, `events_in_window`, `classifier/classifier_version`, `evidence_refs JSON`, `evidence_modality_count`, `trust_tier` (non-authoritative cache), enum CHECKs matching data-model.md vocabularies. **`advisory_id TEXT NULL` (no FK)** + `advisory_linkage TEXT CHECK IN ('echoed_resolved','echoed_pending','echoed_unresolved','temporal','none')` **[F-6]**: a reaction is always recorded; an echoed `advisory_id` starts `echoed_pending`, a P0 background resolver upgrades it to `echoed_resolved` when the `advisory_log` row lands, and marks `echoed_unresolved` after 24 h. Unresolved/temporal/none rows remain fully research-valid (Team C ruling); linkage quality only feeds `ambiguous_linkage_rate` and the advice-linkage metric subset.
- **`reaction_trust_event`** — append-only; authoritative eligibility always recomputed by `reactions/eligibility.py`.
- **`advisory_log`** — `advisory_id TEXT PK` (ULID), `event_id` (indexed, non-FK), `actor_key`, `edge_id`, `content_hash`, `intel_generation`, `local_generation`, `stats_generation` **[F-2]**, `attack_version`, `config_hash`, `created_at`. Written only by `worker` at P0. 90 d prune never deletes rows referenced by any `reaction.advisory_id`.
- **`observation`**, **`observation_stats`** (windowed; carries a monotonic **`stats_generation`** bumped by every stats aggregation batch **[F-2]**, snapshotted once per context call), **`reputation`** (rolling per-`entity_key` local reputation).
- **`edge_reported_ioc`** (keyed on `entity_key`), **`pattern`/`pattern_index`**, **`rule_draft`** (`status CHECK IN ('draft','reviewed','superseded')`, unique `sid`, provenance JSON, `content_hash`), **`bundle_state`** (informational mirror; authority is the LUKS anchor file, S7), **`api_client`** (hashed tokens, scopes, quotas), **`feed_quarantine`**.

STIX 2.1 mapping is exactly data-model.md's boundary table incl. `x-azazel-reaction`; round-trip tests are contract-level.

## 4. API endpoints and behaviors

Scoped bearer token on every route; every request/response line goes to the audit stream (S7).

- **Ingest** — `POST /v1/events | /v1/flows | /v1/reactions`, TAXII 2.1 inbox. Sync handlers on the ingest threadpool **[F-4]** validate lines (pydantic, RFC3339 +/-48 h skew, <= 64 KB/line, `ipaddress`/`idna` canonicalization), stream to a durable spool (`var/ingest/<endpoint>/<batch_id>.jsonl`, fsync + atomic rename, 64 MB per-client quota -> `503`), return `202` + `batch_id`. `GET /v1/ingest/{batch_id}` reports validation outcomes; `worker` drains idempotently by `batch_id`; crashes replay losslessly. **TAXII inbox type whitelist [F-9]**: accepted objects are `indicator` (-> `edge_reported_ioc` quarantine, never `ioc` directly) and `observed-data` carrying `x-azazel-reaction` (routed through the *identical* validator/classifier/trust-tier pipeline as `POST /v1/reactions`, entering at `provisional`). Every other type — `campaign`, `attack-pattern`, `malware`, `relationship`, etc. — is rejected `422 INBOX_TYPE_NOT_ACCEPTED` and logged. No inbox path writes scored or ATT&CK tables.
- **Lookups** — `GET /v1/ioc|ja3|ja4/search`: one-row read on `ioc.agg_*` plus one indexed point-read on `reputation`. Response carries `confidence`, the full four-driver `confidence_reason[]` (zero-contribution lines mandatory), `basis{groups, source_count, freshest_last_seen}`, and for JA3/JA4 `confidence_basis: "type_cap"|"corroborated_cap"`.
- **`POST /v1/context`** — fixed-order pipeline (S5); full advisory contract: `threat_context`, `threat_score`, `confidence`, `reason[]`, `recommendation` with `rejected_alternatives[]`, `source_freshness`, `advisory_notice`, `advisory_id`. **Request bounds [F-10]**: body <= 256 KB and <= 64 candidate entities per call, else `413 context_request_too_large` — the deadline is no longer the only work bound. **Server-side deadline 220 ms, fail-closed**: on overrun the handler aborts with unscored `503 {"error":"context_timeout"}` — never a partial `reason[]`. Breaker firings increment `context_breaker_total`, gated in S9 **[F-12]**. Write path: handler mints `advisory_id`, computes `content_hash`, appends one line to the audit stream on the request thread, returns via read-only pools; `worker` performs the `advisory_log` INSERT at P0. **If the in-process chain append fails (disk error, chain writer dead), context returns `503 audit_unavailable` — advice is never served unauditable [F-17]**; the batched-fsync bounded-loss window on crash is the documented residual.
- Other reads per api.md: `GET /v1/campaigns[/{id}]`, `/v1/recommendations/rules`, `/v1/reactions/summary`, `/v1/edge-intel`, `/v1/health` (per-feed age + pin status, `cache_state`, `audit_writer_ok`, breaker rate, pending confirmations). Admin-scoped: `POST /v1/reactions/{id}/confirm`, `POST /v1/iocs/{id}/confirm`, quarantine release, key management. TAXII collections ship as tested library code; export route is Phase 4; the inbox route is Phase 1.

## 5. Scoring engine spec

Pipeline, fixed order, every stage emits its `reason[]` line: `normalize -> ioc_match -> history -> attack_map -> campaign_match -> geo_asn/cve_exploited -> score -> confidence -> recommend`.

**Determinism contract [F-2]** — `core/clock.py` reads `query_as_of` exactly once at handler entry and threads it through every freshness/promotion/corroboration evaluation. Replay-tested tuple now includes stats state: `(intel_generation, local_generation, stats_generation, attack_version, config_hash, event, query_as_of) => byte-identical reason[]/threat_score/confidence/content_hash`. The context handler snapshots `stats_generation` once with its `observation_stats` read; it is logged in `advisory_log` and folded into `content_hash`. `advisory_id` differs every call and never enters scoring math.

**threat_score** `= clamp_0_100(SUM weight_i x component_i x freshness_i)`; freshness `= max(floor, 0.5^(age_days/30))`, floor 0.2 (`cve_exploited.freshness_floor: 0.7`, advancing only on KEV `catalog_version` change). Default weights, sum 1.0, loader-validated:

| Component | Weight | Notes |
|---|---|---|
| ioc_match | 0.30 | source-count/quality curve (1 src -> 0.4, 2 -> 0.7, >=3 -> 1.0); no zero-forcing branch |
| history | 0.20 | `observation_stats` snapshot; `BurstGuard` caps per-entity events (500/window), over-cap stored but excluded |
| attack_map | 0.15 | `attack-map.yaml` rules via `pattern_index`; `single_basis_cap: 60`; line carries `rules_scanned/rules_total/truncated` |
| cve_exploited | 0.15 | 100 iff any alert CVE in `kev`, else 0; `applies_when: [eve_alert]` — inapplicable lines renormalize remaining weights to 1.0, shown as `contribution: 0, applicable: false` |
| campaign | 0.10 | `0.7 x ioc_overlap + 0.3 x technique_overlap`, `single_ref_cap: 40`, `type_diversity_bonus: 10`; low-corroboration IOCs excluded from numerator |
| geo_asn | 0.10 | data-backed in Phase 1 by the new `spamhaus_asndrop` adapter **[F-13]** -> curated list -> IOC-referenced ASNs; untagged/novel ASN yields per-entity contribution 0, never a global toggle |

Every `reason[]` line carries `component, config_weight, effective_weight, freshness, contribution, detail`; contract tests assert `SUM(contribution) == raw_score` and `clamp_0_100(raw_score) == threat_score`. Non-contributing components appear at 0. The weight table plus all pending doc diffs (KEV `sources[]`, `rejected_alternatives`, IDN direction [F-15]) ship for ratification; `docs-sync-check.py` blocks release until merged, then forever diffs doc examples against `config/scoring.yaml`.

**confidence — one canonical formula [F-8].** `confidence = clamp_0_100(SUM w_j x driver_j)` over exactly four drivers, own versioned sum-to-1.0 `confidence_weights` block: `source_count` 0.30 (`min(distinct_groups,4)/4`), `source_independence` 0.30 (`1 - max_single_group_share`), `source_freshness` 0.25 (oldest contributing source), `local_corroboration` 0.15 (floor 0.3). Feed grouping (`urlhaus/malwarebazaar/threatfox` share `group: abusech`; `edge_reported` its own group, base 35) defines `distinct_groups` and group shares. **The noisy-OR (`raw = 100 x (1 - PROD_g(1 - g/100))`) is not a term of `confidence`**: it computes only `ioc.agg_raw_confidence`, used for primary-IOC selection and the `basis` detail block. **Parity contract renamed and pinned**: *confidence-formula parity* guarantees lookup and context use identical weights, driver definitions, and code path, and produce byte-identical output for identical driver inputs; the sole documented input divergence is `local_corroboration` (lookup reads the `reputation` materialization; context may additionally reflect the live `observation_stats` snapshot at its pinned `stats_generation`). The contract test asserts both formula-identity and the divergence being confined to that one driver. JA3/JA4 type caps (`ja3: 0.6, ja4: 0.7`; corroborated `0.9/1.0`; corroboration = exact ip/domain/url/hash match or history >= 50) apply to the ioc_match component value, disclosed in `detail`. Multi-IOC answers carry `multi_ioc_scope{matched_count, primary_ioc_id}` (argmax `agg_raw_confidence x freshness`, ties by `entity_key` ASC). Past `stats.max_staleness_s: 120`, `history` and `local_corroboration` are forced to 0.

**Recommendation** (`recommend/select.py`): ordered `recommendation.action_bands`, first match wins, default `observe`. `rejected_alternatives[]` is a pure function of `(score, confidence, config_hash)`; it reads no reaction data. Rule drafts: slot grammars per type (grammar failure -> no draft, logged), Suricata `content` escaping, Sigma via `yaml.safe_dump`, `lint.py` round-trip byte-identity, provenance + confidence on every draft. No deploy channel exists anywhere.

**match_spec / patterns**: JSON `"v":1`, combinators `all|any|not` depth <= 4, ops `eq,in,prefix,suffix,cidr,gte,lte,exists`, no regex; unknown op/version skipped, logged. `pattern_index` populated synchronously at load; ceilings `max_patterns_scanned: 200`, `max_eval_ms: 5`, `max_patterns_scanned_unindexed: 50`; truncation ordered `(priority DESC, pattern_id ASC)`, disclosed. Pattern store ships in Phase 1 schema; reaction-driven compilation is Phase 2.

## 6. Feed adapters and offline bundles

**Adapters** — Phase 1 set: ATT&CK, CISA KEV, urlhaus, malwarebazaar, threatfox, **spamhaus_asndrop [F-13]**, GeoIP/ASN files. `FeedAdapter` ABC `fetch -> stage -> parse -> validate -> apply`, checkpointed in `feed_state` (5k-item checkpoints, < 50 ms lock hold), rate-limited, idempotent, staging-first. **Transport hardening [F-16]**: `feeds.yaml` carries per-adapter `pin_spki_sha256` lists; pin mismatch halts the feed and flags `/v1/health` (pins rotate via signed bundle or `azctl feed set-pin`, audit-chained). Independent of transport, `normalize/cross_feed_check.py` quarantines a pull whose *novel*-IOC overlap fingerprint against sibling feeds deviates > 3 sigma from the trailing baseline — feed-content injection within volume bounds still trips a content-shaped tripwire. Layered ingest defenses retained: bogon/own-infra rejection at normalize; critical-infra allowlist -> flag-and-quarantine (contribution 0 until second-group corroboration; admin-only promotion); 3x trailing-7-run median volume halt pending `azctl feed inspect|approve`; `min_consecutive_polls` gate for abuse.ch feeds (KEV exempt); high-severity first-seen soft-hold (4 h).

**Edge-reported promotion**: `edge_reported_ioc` promotes to scored `ioc` only via (a) cross-group external corroboration on the same `(type, value)`; (b) >= `promotion.min_distinct_edges` (3) within 7 days against `query_as_of`; or (c) analyst `POST /v1/iocs/{id}/confirm`. Promotions log their reason and are quarantine-revocable; unpromoted rows are visible at `/v1/edge-intel`, excluded from scoring and Pattern Generator input.

**Bundle format** — sync-offline.md: `manifest.json` (version, base version, feed list, per-file SHA-256, `created_at`, `attack_version`) + detached ed25519 signature(s), `pynacl`. Bundles contain **intel-tier content only**; a bundle naming any local-tier table hard-aborts (`BUNDLE_TOUCHES_LOCAL_TIER`) **[F-1]**. Trust decisions read exclusively from `/etc/azazel-knowledge/trust/anchors.toml` (root 0600, LUKS secrets partition): `threshold` (default 1, provisionable >= 2), active/revoked keys; sole writers are audit-chained `azctl keys` commands. A manifest embedding trust fields hard-aborts (`BUNDLE_SHADOWS_TRUST_ANCHOR`). **Anti-rollback authority moves on-anchor [F-7]**: the monotonic `last_imported_version` lives in `/etc/azazel-knowledge/trust/state.toml` on the same LUKS secrets partition, written atomically (write-fsync-rename) as the final import step; `local.db:bundle_state` is a convenience mirror. Rolling back the data partition and `bundle_state` together no longer resets the guard — the comparison source is inside LUKS. Import order: verify signatures/threshold/per-file hashes/anti-rollback against `state.toml` before touching any content file -> stage with bomb guards (size cap, manifest-first, streaming ratio) -> build `gen-<N+1>/intel.db` in the low-priority subprocess -> warm before live (`posix_fadvise(WILLNEED)`, priority `ioc` host tier -> range/ASN tiers, 8 s/10M budget; old generation serves throughout) -> atomic symlink rename + `state.toml` update -> GC old gen once pinned readers drain. Differentials refuse a mismatched base; gap of 1 at crash-mid-swap triggers `integrity_check`; unexplained gaps raise `INTEGRITY_ALERT`, failing closed pending `azctl bundle resolve-state`. `azctl restore` sets `needs_full_rebaseline=1` and rejects non-full bundles below the pre-restore version (restore also cannot regress `state.toml`, which is not on the backed-up data partition). `tools/bundle_build.py` ships in Phase 1.

**Bundle verifier strictness (K8–K11)** — `threshold` is a non-boolean integer >= 1, bounded by non-revoked key count and, when required, by non-revoked signer-role holder count; unsatisfiable anchors abort at load with `BUNDLE_ANCHORS_THRESHOLD_INVALID`. `bundle_version` is a non-boolean integer >= 1 (`BUNDLE_VERSION_INVALID`), because the initial rollback watermark is 0 and imports strictly advance it. Member names retain the 256-member, depth-8, 1024-UTF-8-byte defaults and additionally cap each component at 255 UTF-8 bytes (`BUNDLE_MEMBER_COMPONENT_TOO_LONG`); all declared paths are checked before extraction. Top-level `key_roles`, `required_signer_role`, `minimum_security_epoch`, and `accepted_export_policy_digests` are trust shadowing too; artifact epoch/policy claims remain allowed in their existing fields. See [sync-offline.md](../sync-offline.md#verification-limits-and-trust-policy) for the complete contract and Nexus comparison.

## 7. Security measures

- **Network**: bind `network.bind_addr:8443` on the management segment only; `0.0.0.0` refused unless `allow_any_bind: true` (CI-grepped). nftables default-drop inbound, allow 8443 from `edge_allowlist` only; outbound one egress rule per adapter plus the pinned resolver. Zero WAN listeners.
- **AuthN/Z**: `azcti_<key_id>_<secret>` tokens, `sha256(secret)` at rest, `hmac.compare_digest`; scopes deny-by-default (`ingest`, `query`, `read`, `admin`); Edge gets `ingest+query`, never `admin`.
- **Redaction**: node-token regex plus boot-time `SecretRegistry` of every value under `secrets/`, matched by value on every log sink and exception path; fuzz-tested.
- **At-rest** (seizure model): LUKS2 mandatory for `secrets/` (incl. `anchors.toml` + `state.toml`), tokens, audit chain, `local.db`. **Both partitions use Adiantum (`cipher xchacha12,aes-adiantum-plain64`) [F-18]** — Cortex-A72 has no AES extensions, and the LUKS partition takes a write on every query, so software AES-XTS is explicitly excluded; per-board `cryptsetup benchmark` recorded in `ops/hardware-profile.md`. Flag-gated fallbacks only: `--data-partition-unencrypted --accept-seizure-recreatable-data` (intel tier is re-importable; local tier is never eligible for this flag) and keyfile auto-unlock with `--accept-capture-confidentiality-loss`. `azctl scrub` = crypto-erase.
- **Audit [F-5]**: chaining is **per-process**: each api worker and the worker process appends to its own chain file `var/audit/<stream>/<proc_id>.<boot_id>.jsonl`, hash-chained per line synchronously in-process — no cross-process lock on the hot path. Batched fsync (200 ms / 500 lines). Joint Merkle anchors signed by `node_signing_key` (3600 s / 500 entries) cover the current heads of *all* chains; `azctl audit verify` checks every chain and anchor inclusion, so the multi-chain set is tamper-evident as a whole. Chain-append failure in a process flips it unhealthy: context in that process returns `503 audit_unavailable` **[F-17]**; `audit_writer_ok=false` additionally blocks new bundle imports. Ring-full in the worker's tail path can delay `advisory_log` materialization but never drops the durable chain line — the P0 tail resumes from the chain file itself (the ring is an optimization, the file is the source of truth), which also closes the advisory-loss path behind [F-6].
- **Threat model** doc ships with residual risks recorded (key custody, single-node anchoring, promotion gaming, unattended-boot trade-offs, cold-read margin — S13).

## 8. Reaction / pattern / research components

Faithful reaction capture is a Phase 1 exit obligation; rate claims wait for Phase 2 past a pre-registered minimum N. Classification is background-only (P1) after `reaction_window_s`, first-match ladder, versioned; rows immutable. Trust tiering: `provisional -> same_edge_corroborated` (>= 2-modality, informational) `-> human_confirmed | corroborated` (distinct-`edge_id` > 1, inert in Phase 1); headline metrics use `metrics_eligible_strict`, recomputed from `reaction_trust_event` at export. **Shadow scoring is flag-gated and default-off [F-19]**: `research.shadow_scoring.enabled: false` ships; when enabled, `reaction_adjustments` load solely with `mode: shadow` (loader rejects `active`; `|delta| <= 30`, `max_total_delta: 20`), and `shadow_adjusted_score` goes only to the JSONL research log — never a response field. The flag and its Phase-2 scope note enter the roadmap diff. Advice linkage per S3 [F-6] (`echoed_* / temporal / none`; `linkage_window_s: 3600`; `ambiguous_linkage_rate` reported). Export: `actor_key -> HMAC-SHA256(site_key, .)[:16]`, manifest-hashed sorted JSONL; raw IPs never leave the site; STIX `x-azazel-reaction` unit-tested now, TAXII export Phase 4.

## 9. Performance plan

Budgets are gates. Per-PR `ci: perf-regression` (5-min soak, > 10 % regression fails) plus the nightly/pre-release exit gate on a real Pi 4, LUKS/Adiantum on, N >= 10M — all blocking:

- **Capacity run (breaker disabled) [F-12]**: lookup p95 < 50 ms; context p95 < 250 ms end-to-end (confidence breakdown, recommend, match_spec tiers, attack_map index, geo_asn on). Disabling the 220 ms breaker for this run makes the latency gate falsifiable again — it measures true service time, not breaker-truncated time.
- **Availability run (breaker enabled)**: `context_breaker_total / context_total < 0.5 %` at reference load and `< 2 %` at 2x load — capacity shortfalls surface as a gated 503-rate failure, not silence.
- **Cold-read margin analysis [F-20]**: the gate suite includes a forced-cold (`posix_fadvise(DONTNEED)`) leaf-read microbenchmark under Adiantum quantifying per-page decrypt+read cost at the 1.2 GHz thermal-cap canary, and a worst-case context trace (all leaf pages cold) that must land < 250 ms with >= 20 % headroom; failure triggers a redesign spike (index layout / cache split), never a lowered figure. This converts the round-5 "no analytical headroom" objection into a measured, blocking number.
- Combined DB-page Pss <= 320 MiB; total RSS < 2 GB via computed ceilings + drift soak; 10M import capacity; post-swap first-500-query p95 warm and forced-cold; `thermal_soak.sh` blocking on any throttle bit; WAL growth bounded; `test_context_no_blocks_on_import` plus a **writer-starvation test [F-3]**: sustained P2/P3 load + a live bundle build while P0 audit-tail lag stays < 5 s and ingest-drain lag < 30 s.
- **Cold boot**: during `startup.warmup_grace_s` (30 s) with no warm generation, lookup/context return `503 Retry-After`; ingest keeps spooling. Once `cache_state: warm`, budgets are unconditional; no path ever serves an out-of-budget answer.

**Bundle compression codec** — `.tar.gz` (stdlib gzip) ships in Phase 1 (`bundle/verify.py` records the honest gzip-not-zstd rationale). A ratio bench (`tools/bench/compression_bench.py`, size/ratio hardware-independent) on a 500k-row sample extrapolates a full-10M `intel.db` to roughly gzip ~686 MiB / stdlib `lzma` ~225 MiB / `zstd -19` ~334 MiB. Because stdlib **`lzma` beats `zstd` on ratio, the `zstandard` dependency is not justified on size alone** (it would cross the dependency-minimality constraint for no compression win over a stdlib codec). The one open variable is Pi 4 `lzma` decompress cost at import (lzma decompress ~5–6x gzip on the dev box; xz is CPU/memory-heavy on the Cortex-A72), tracked for on-board measurement in the Pi 4 hardware-validation issue. Candidate outcomes: keep gzip, or switch to stdlib `lzma` (no new dependency) if the Pi import-time decompress budget allows; adopting `zstd` is disfavored.
